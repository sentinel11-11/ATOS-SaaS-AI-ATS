# Проверка замечаний к виджету, 25.11.2026

Разбор относится к предоставленному тексту и итоговому коду 5.4.0. Некоторые предположения из текста не подтверждаются фактическим протоколом; изменения ниже сохраняют проверку участника и защиту от повторного набора.

| № | Результат проверки и изменение |
|---|---|
| 1 | Исправлено: `sipConnect` возвращает общий Promise до события `registered`, отклоняет его при отказе/таймауте и освобождает состояние в `finally`. Синхронные ошибки обрабатываются цепочкой. |
| 2 | Сервер позволяет продлить истёкшую аренду с тем же UUID, поэтому повторное использование ID само по себе не создаёт «зомби». Heartbeat может продлить истёкший собственный слот под mutex, если он ещё не переназначен; фоновая вкладка не теряет разговор только из-за задержки таймера. После потери неактивной сессии ID меняется; при неясной заявке сохраняется для её безопасного повтора. Каждая параллельная сессия получает отдельный SIP endpoint. |
| 3 | Предположение не подтвердилось: собственный исходящий звонок тоже получает `/agent/invite`, затем заполняет `receiveCall`. Настоящие Chromium, WSS, Asterisk, TURN и SRTP проверяют отправку готовности и мост. Нельзя отправлять готовность до проверки nonce входящего SIP-вызова. |
| 4 | Исправлено: приоритет у RTCPeerConnection из события `peerconnection`; более поздняя ссылка `session.connection` его не заменяет. Старые медиасобытия и завершение прежней сессии не изменяют новую. |
| 5 | Добавлен beacon завершения только для страницы фактического участника. Origin + session UUID + секретный nonce ограничивают его конкретным вызовом. Закрытие страницы инициатора чужого разговора сохраняет речь. При полном обрыве сети доставка beacon не гарантируется. |
| 6 | Клиент всегда разрешает кликнутый телефон через контакты текущей карточки. Сервер независимо проверял и продолжает проверять связь и телефон живым запросом в CRM. Переданный SDK `contact_id` не заменяет эту проверку. |
| 7 | Сброс ключа после сетевой ошибки опасен: принятая сервером заявка могла остаться без HTTP-ответа. Ключ и исходное тело сохранены; добавлена кнопка продолжения исходной заявки из другой карточки. Отказ микрофона после неоднозначного POST тоже не теряет ключ. |
| 8 | Добавлено чтение страниц `/api/v4/{entity}/{id}/links` при неполном embedded-списке. URL строится из проверенного типа и ID; внешние `next.href` не открываются. Обход ограничен 20 страницами по 250 связей. |
| 9 | Добавлен `heartbeatInFlight`; медленный ответ не создаёт очередь heartbeat. |
| 10 | Отказ повторного включения звука отображается в виджете с предложением проверить разрешение и устройство вывода. |
| 11 | `draw` обновляет существующие поля, полного HTML-перерендера на каждом тике в исходном коде не было. `safeText` теперь пропускает запись неизменившегося значения. |
| 12 | Шаблон остаётся статическим. Имена, телефоны и сообщения из API выводятся через `textContent`. |
| 13 | При загрузке актуального стиля удаляются прежние `link[data-rats-style]`. |
| 14 | Добавлен UUID v4 через `crypto.getRandomValues` для браузеров без `randomUUID`; не используется `Math.random`. Ошибка безопасного контекста выводится в интерфейсе. |
| 15 | На `pagehide` таймеры очищаются вместе с их ID; `pageshow` проверяет существование перед созданием. Эпоха подключения блокирует запуск устаревшей SIP-инициализации после ухода страницы. |

Дополнительно: сообщения о другом браузере устранены изменением серверной модели устройств. Для каждого оператора подготовлены 8 приватных слотов. Параллельные browser-вызовы резервируют разные устройства; телефонная переадресация и обычные ACD-вызовы сохраняют исключительное резервирование оператора. Оператор освобождается после завершения всех его активных попыток.

На изолированном стенде проверяются настоящий медиапоток в обе стороны и независимое завершение двух одновременных разговоров общего аккаунта. Живой VPS и amoCRM владельца из этой среды не доступны по SSH; применение и реальные звонки после обновления проверяются отдельно.
