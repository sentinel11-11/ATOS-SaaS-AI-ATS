# MegaFon: контроль одиночных звонков из amoCRM без callback

## Наблюдаемая проблема

После `/crmapi/v1/makecall` попытка переходит в `accepted`. Если сотрудник не принимает
вызов, МегаФон иногда не отправляет callback завершения; в журнале nginx и `inbox`
нет события. В результате попытка и статус оператора остаются активными.

## Изменения

- Для операторских кампаний MegaFon, созданных через `amo-widget:` или
  `amo-click:`, добавлен отдельный тайм-аут неподтверждённого `accepted`.
- По умолчанию это 5 минут после `Attempt.updated_at`; допустимый диапазон 2–60 минут.
- Тайм-аут применяется только при `answered_at IS NULL`, только к `accepted`;
  к `answered` короткий тайм-аут не применяется.
- Выполняется обычная `finish_attempt(..., "failed", "megafon_unconfirmed_timeout")`:
  освобождение оператора, закрытие кампании, аудит и постановка CRM-задачи.
- Ошибки распределения кампаний не мешают запуску watchdog в той же итерации.
- Общий watchdog 20 минут и защитный режим `unknown` сохранены для прочих сценариев.

## Настройка

Значение берётся из `workspace_settings.values._legacy_basic.megafon_unconfirmed_timeout_min`
для каждого tenant. Если настройки нет, применяется 5 минут.

**Важно:** это тайм-аут *неподтверждённого состояния*, а не подтверждённый `NOANSWER`.
ВАТС может иметь живой разговор, о котором ATS не получила callback. При таком сбое
автоматическое освобождение оператора может допустить параллельный звонок.
Для достоверного определения ответа нужна сверка с МегаФон через документированный
метод истории/статуса, доступность и контракт которого необходимо подтвердить в
кабинете ВАТС. Без этого надёжно отличить живой разговор от непринятого по времени невозможно.

Для отключения ускоренного тайм-аута у конкретного tenant можно установить
`megafon_unconfirmed_timeout_min` в 20 или выше; для полного возврата к
существовавшему общему watchdog следует убрать применение отдельного правила
после согласования такого изменения.

## Проверка перед production

1. В тестовой PostgreSQL `ats_test*` запустить
   `pytest -q tests/test_beta.py -k 'megafon_unconfirmed or scheduler_runs_watchdog'`.
2. Проверить три сценария: оператор не ответил, разговор длится более 5 минут,
   webhook с терминальным событием пришёл поздно.
3. Убедиться, что ни один продолжающийся разговор не помечается ошибочно как завершённый.
4. После merge выполнить `git pull --ff-only origin main` и
   `systemctl restart ats-beta-worker@scheduler`.
5. Проверить `call_attempts.reason`, `operators.status`, `campaigns.archived`,
   журнал ATS и синхронизацию с amoCRM.
