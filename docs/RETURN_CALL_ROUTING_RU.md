# Перезвон клиента тому же оператору

ATOS хранит последний исходящий звонок по паре «организация, номер клиента» в `callback_affinity`. Запись действует 7 дней. В режиме amoCRM сохраняется ответственный оператор, который обслуживает звонок. Связь обновляется, когда Asterisk создаёт плечо к клиенту, в том числе если клиент не отвечает. Для обычных исходящих используется подтверждение отправки от провайдера. Миграция `0017` заполняет таблицу по доступным подтверждениям за последние 7 дней.

При входящем звонке Asterisk один раз пытается соединить клиента с сохранённым оператором. После исходящего WebRTC ATOS сначала ищет активную вкладку этого оператора в amoCRM. На телефоне или SIP-устройстве вызов виден как обычный входящий. Если оператор занят, назначения нет или на вызов не ответили за 20 секунд, Asterisk продолжает выполнять действующий входящий маршрут.

## Подключение на VPS

1. Обновить ATOS и применить Alembic до `0017` штатным обновлением. В конфигурации ATOS должны быть включены `ATS_LIVE_CALLS_ENABLED` и `ATS_INBOUND_ENABLED`, а `ATS_TELEPHONY_TENANT_ID` должен указывать на владельца входящих номеров. Перезапустить API и воркеры после изменения настроек.
2. Запустить на VPS `bash /opt/ats-beta/deploy/ubuntu/install-return-call.sh` от root. Команда устанавливает AGI и запускает сервис на локальном Unix-сокете, доступном процессу Asterisk.
3. Подключить файл `#include extensions-ats-beta-return-call.conf` в конфигурации Asterisk. В ветке существующего входящего Multicom DID вставить эту строку **до** `Answer()`, очереди или перевода на базовый маршрут.

   ```asterisk
   same => n,Gosub(ats-beta-return-call,s,1(${EXTEN}))
   ```

   Вызов должен происходить на входящем канале транка. Следующие строки существующего маршрута служат запасным путём. Начать можно с одного DID.
4. Выполнить `asterisk -rx 'dialplan reload'` и проверить контекст командой `asterisk -rx 'dialplan show ats-beta-return-call'`. Сделать исходящий через виджет, затем с того же клиентского номера перезвонить на DID. Проверить входящий в браузере ответственного и переход к обычному маршруту, если он недоступен.

Установленный виджет **5.4.0** принимает звонок через свой подписанный WebRTC-протокол. Для телефонной переадресации используются личный номер оператора, разрешённые направления, действующие лимиты и подтверждённый А-номер Multicom. Удаление `Gosub` из выбранной ветки и перезагрузка диалплана возвращают стандартную входящую маршрутизацию.
