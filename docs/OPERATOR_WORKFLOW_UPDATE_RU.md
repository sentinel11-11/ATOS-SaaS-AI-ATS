# Обновление работы операторов и А-номеров

25.11.2026, Москва. Схема PostgreSQL — **0016**, ZIP amoCRM остаётся **5.4.0**.

## Лимиты и охлаждение

Общего суточного ограничения количества звонков больше нет. Квота задаётся **для каждого А-номера отдельно**, действует и для звонков amoCRM, и для автоматических кампаний. Общая ёмкость внешних каналов и ограничения каналов кампании сохраняются.

В «Пуле номеров» → настройки карточки доступны:

| Поле | Начальное значение | Действие |
| --- | --- | --- |
| Лимит до охлаждения | 150 | Число использований А-номера в одном цикле |
| Охлаждение после лимита, секунд | 3600 | После исчерпания квоты номер временно исключается из ротации |
| Пауза между попытками, секунд | 60 | Отдельный минимальный интервал между началами попыток |

Администратор может менять эти значения независимо для каждого номера. После охлаждения счётчик цикла автоматически обнуляется; номер возвращается в ротацию с новой квотой. Полночь счётчик не сбрасывает. Повышение лимита во время охлаждения возвращает номер в пул, если уже использованное количество меньше нового лимита; выполненные попытки сохраняются. Изменение длительности пересчитывает уже начатое охлаждение от его первоначального начала. Значение 0 отключает соответствующую паузу.

Бюджет консервативно учитывает подготовленные попытки, включая завершившиеся ошибкой: WebRTC использует одну внешнюю единицу, переадресация на мобильный — две. Вес определяет долю номера среди доступных; отключение, карантин, подтверждение провайдера и привязки А-номеров к операторам продолжают действовать. Кнопка сброса статистического периода не обнуляет рабочую квоту.

Поля протокола `daily_limit` и `Tenant.daily_limit` оставлены для совместимости. Для А-номера `daily_limit` означает квоту цикла. Значение старого общего `Tenant.daily_limit` больше не ограничивает scheduler.

## Звонки и удаление

Одиночные кампании, созданные виджетом amoCRM, работают круглосуточно во все дни недели. Интерфейс показывает фактическое расписание `00:00–24:00`; редактирование кампании сохраняет ответственного и выбранный способ соединения. Расписание обычных автоматических кампаний сохраняется.

Истёкшая заявка amoCRM снимается с очереди даже при занятых каналах. Кампанию, ожидающую в очереди без активной попытки, можно остановить и удалить из интерфейса. Без Attempt звонка ещё не было, поэтому искусственная запись в журнале не создаётся.

Удаление контакта или пользователя физически удаляет соответствующую запись адресной книги/учётной записи. Телефон, логин и внутренний номер можно использовать заново. Завершённые звонки, события, записи разговоров и сведения об участниках сохраняются независимо. Незавершённый или требующий сверки звонок необходимо сначала закончить: удаление во время такого звонка отклоняется. Последнего активного администратора удалить нельзя. Главная страница считает только действующих пользователей с ролью оператора.

Исторические кампании сохраняются для журнала; завершённые одиночные кампании скрываются из рабочего списка. Подтверждение клавишей «1» и автоматические задачи после звонков виджета не возвращаются.

## Логи Asterisk

На проверенном VPS обычный `logrotate.timer` включён, но штатное правило не охватывало `messages.log`, а отдельное правило ATOS отсутствовало. Поэтому наличие активного таймера само по себе не обеспечивало очистку этих файлов. Сжатие уже выполненных архивов владельцем уменьшило занятое место на диске с 40 ГБ до 7,3 ГБ.

Установщик `scripts/install-asterisk-log-retention.py --apply`:

- проверяет новое правило настоящим `logrotate --debug` до установки;
- включает почасовую проверку `messages.log`: ротация ежедневно или при размере более 100 МБ, хранение 14 ротаций со сжатием;
- перечитывает logger, без перезапуска Asterisk;
- включает ежедневную очистку папок `archive-*`, содержащих только завершённые `messages.log.N.gz`;
- хранит старые архивы 30 дней **с момента первого включения политики**, независимо от старого времени внутри gzip; открытые, несжатые и неизвестные файлы не удаляет.

Это удержание журналов, а не записей разговоров. Правило не затрагивает аудиозаписи, PostgreSQL и резервные копии базы. Размер 100 МБ проверяется раз в час, поэтому это порог ротации, а не жёсткий предел роста между проверками.

## Применение на VPS

Запускать от root после завершения разговоров. Обновление проверяет отсутствие активных/неопределённых попыток, создаёт резервную копию и применяет миграцию.

```bash
runuser -u ats-beta -- git -C /opt/ats-beta pull --ff-only origin main &&
bash /opt/ats-beta/deploy/ubuntu/update-beta.sh &&
bash /opt/ats-beta/deploy/ubuntu/manage-beta.sh /opt/ats-beta/scripts/apply-operator-workflow-update.py --apply --caller-limit 150 &&
/opt/ats-beta/.venv/bin/python /opt/ats-beta/scripts/install-widget-webrtc.py &&
asterisk -rx 'pjsip reload' &&
/opt/ats-beta/.venv/bin/python /opt/ats-beta/scripts/install-asterisk-log-retention.py --apply
```

`--caller-limit 150` однократно выставляет исходную квоту всем номерам настроенного tenant. Скрипт сохраняет таймеры, карантин, веса и ёмкость каналов; удаляет старые архивированные контакты/учётные записи с сохранением истории. При последующих запусках **не передавать `--caller-limit`**, чтобы сохранить индивидуальные лимиты. Без `--apply` скрипт только показывает объём изменений.

Подготовка WebRTC удаляет из конфигурации Asterisk устройства удалённых операторов и сохраняет секреты действующих. ZIP заново загружать не требуется. Обновить страницу ATOS через Ctrl+F5 и проверить:

```bash
systemctl list-timers --all 'ats-asterisk-*'
cat /etc/logrotate.d/ats-asterisk-messages
```
